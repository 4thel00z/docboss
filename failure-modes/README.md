# Failure modes

Before/after renders of layout and rendering bugs fixed in this repository.
Each pair is named after the short hash of the commit that fixed it plus a
slug: `<hash>-<slug>-before.png` is `docboss render` at that commit's
parent, `<hash>-<slug>-after.png` the render at the commit. Unless a row says
otherwise, the page is rendered at scale 1 (72 dpi) from a file in the
LibreOffice or Apache POI test corpora, and SSIM is the windowed SSIM of
`benchmarks/bench_fidelity.py` against LibreOffice's own rendering of the
same file at scale 1.5.

| Commit | Failure |
| --- | --- |
| `4a16833` (calibri-substitute) | Calibri resolved to Arial and Cambria to Times New Roman whenever Carlito and Caladea were not in a system font directory, although LibreOffice installs both with its own fonts and macOS ships Carlito as a supplementary font. LibreOffice `ooxmlexport/data/cell-grid-span.docx` sets its body in Calibri and its lower half in Cambria: the before render sets both in the wrong faces, so every line breaks at a different word (SSIM 0.547). With the LibreOffice font directory and macOS's supplementary font directory searched, both resolve to their metric-compatible substitutes and the line breaks match LibreOffice's (SSIM 0.683). Over the 88-file sample, mean SSIM rises from 0.8862 to 0.8883 and page counts agree on 82 files instead of 81. |
| `d0a7e13` (line-leading) | Single-spaced lines were `usWinAscent + usWinDescent` tall, which leaves out the part of the `hhea` line gap the Windows metrics do not already cover: 12 pt Arial and Times New Roman lines came out 13.4 pt where Word and LibreOffice set 13.8 pt (Calibri's Windows metrics absorb its line gap, so Calibri documents were unaffected). Apache POI `Bug50936_1.doc`, 12 pt Arial: at scale 1.5 the before render's line pitch is 20.1 px against LibreOffice's 20.7 px, so every page held about one line more and the pages drifted apart; the after render's first page places all 44 text lines within 1 px of LibreOffice's. Its first five pages score SSIM 0.47, 0.46, 0.39, 0.38, 0.69 before and 0.98, 0.80, 0.97, 0.97, 0.97 after. Over the 88-file sample, mean SSIM rises from 0.8883 to 0.9032; two files (`tdf170602_exportContext.docx`, `Bug47287.doc`) now run one page longer than LibreOffice. |
| `ea482a4` (table-style-spacing) | A table style's paragraph and run properties never reached the paragraphs in its cells, which resolved from the document defaults and their own paragraph style only. LibreOffice `ooxmlexport/data/tdf64264.docx` has a Table Grid style with `spacing after=0` and single line spacing over document defaults of 8 pt after and 259/240 lines, so every row of its 40-row table carried the defaults' spacing and the table ran to 4 pages where LibreOffice sets 2. The table style now sits between the document defaults and the paragraph style, as ECMA-376 Part 1 §17.7.2 orders them, and the rows are single lines: 2 pages. |
| `ddbfd3d` (auto-color-on-dark) | Text and list labels whose color is `auto` were always black. The same `tdf64264.docx` fills rows 2 and 3 with `C00000`; Word and LibreOffice draw their auto-colored text and labels white, docboss drew them black (cropped to the top of page 1, scale 2). `auto` now resolves against the run's shading or highlight, the paragraph's shading, then the cell's fill, and turns white when that fill's Rec.601 luminance is below 128; the light blue `9CC2E5` header row keeps black text. |
| `6174d98` (symbol-bullets) | A bullet stored as a symbol font's code in the U+F000 private-use range drew the missing-glyph box whenever that font was not installed. The `libreoffice-rich.docx` fixture (`crates/docboss-docx/tests/fixtures`, top half of page 1 at scale 2) numbers its list with StarOffice's `starbats` font, code U+F095: both items showed a boxed question mark. Symbol-font codes the selected face lacks are now translated to the character they draw (Adobe Symbol encoding for Symbol, the common bullets and marks for Wingdings, Windows-1252 for other symbol fonts, where 0x95 is U+2022) and drawn from a face that has it. No file of the 88-file sample changed by more than 0.005 SSIM, since this machine has Symbol and Wingdings installed. |
| `456cd22` (cell-gap) | Word binary tables state the gap between a cell's text and its edges with `sprmTDxaGapHalf`, which the DOC reader ignored: every cell took DOCX's 108-twip default margins. Apache POI `AIOOB-Tap.doc` (the version table on page 1, scale 2, cropped) has a 921-twip first column with a 70-twip gap, so "Versie nummer" wrapped to "numme / r" and the dates to "26-10-0 / 7"; LibreOffice keeps both on one line. The gap is now each cell's left and right margin unless `sprmTCellPadding` names that side, and a table without `sprmTDxaLeft` is placed at its leftmost cell edge ([MS-DOC] §2.6.3). Page 1 scores SSIM 0.58 before and 0.70 after (the file's first five pages 0.629 and 0.661), and the DOC half of the sample from 0.8681 to 0.8693. |
| `c8c30dc` (border-group) | Each paragraph drew its own top and bottom border. LibreOffice `ooxmlexport/data/tdf166510_sectPr_bottomSpacing.docx` (top of page 1, scale 2) has a header of three paragraphs, two of them empty, each with the same single bottom border: docboss drew three rules where Word and LibreOffice draw one, under "Header". Consecutive paragraphs whose resolved borders are equal now form one group, with the top border above the first, the bottom border below the last and the between border inside (ECMA-376 Part 1 §17.3.1.24, §17.3.1.5). The file's SSIM rises from 0.896 to 0.955. |
| `3bb1dda` (page-number-format) | `PAGE` fields always showed decimal numbers: the section's `w:pgNumType w:fmt` (and the DOC reader's `sprmSNfcPgn`) was never read, and a field's `\*` format switch was ignored. The same `tdf166510_sectPr_bottomSpacing.docx` (footer of page 1, scale 2) numbers its first section in upper-case Roman: the footer showed "1" where LibreOffice shows "I". Section properties now carry the page number format, both readers fill it, and `PAGE` is formatted by its `\* ROMAN`/`roman`/`ALPHABETIC`/`alphabetic`/`Arabic` switch, else by the section's format (ECMA-376 Part 1 §17.6.12, §17.16.4.3). One glyph per page changes, so no sample file moved by more than 0.001 SSIM. |
| `2f78cdd` (doc-table-borders) | A TC80 cell border of four zero bytes states nothing, but the DOC reader read it as an explicit none border, so every cell of a Word 2000+ table that keeps its rules in `sprmTTableBorders` drew none. Apache POI `Bug47287.doc` (page 1) is a 14-row bordered visa form: the before render shows its labels as bare text. Zeroed TC80 borders are now unstated, and where rows state different table borders each cell takes its own row's, so the spacer rows between the form's three blocks stay unruled as in LibreOffice ([MS-DOC] §2.9.313, §2.6.3). The rules are drawn at row heights that do not yet match LibreOffice's exactly, so SSIM falls on the three files it touches (`Bug47287.doc` 0.672 to 0.647, `AIOOB-Tap.doc` 0.661 to 0.637) although both now show the borders LibreOffice shows. |
| `6968855` (merged-borders) | The rows of a vertically merged cell drew the table's inside horizontal border across the merged cell at every row boundary. `AIOOB-Tap.doc` page 4 (lower part) merges its first column over two to four rows per group ("Papiersoort", "Envelop toevoegen", "Lengte"): the before render cuts each group with rules LibreOffice does not draw. The border between a cell and the continuation below it is now left out (ECMA-376 Part 1 §17.4.84); the file's SSIM goes from 0.637 to 0.642. |
| `492fa76` (wide-grid) | Autofit tables wider than the text area were scaled down to fit it, which neither Word nor LibreOffice does. `Bug47287.doc`'s form is 503 pt wide in a 481 pt text area and starts 35 pt into the left margin: scaled down, its first column wrapped "Номер паспорта и срок его действия" onto two lines and the document ran to 2 pages where LibreOffice sets 1. Grids now keep their widths and only a percentage table width scales them (ECMA-376 Part 1 §17.4.48): 1 page, SSIM 0.647 to 0.683, and the DOC half of the sample from 0.8677 to 0.8699 with page counts agreeing on 82 of 88 files instead of 81. |
