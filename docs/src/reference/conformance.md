# Conformance

docboss keeps a ledger of the specifications it implements in `ledger/Ledger/Catalogue/`, one
row per clause with the status docboss claims: implemented, incomplete, not implemented or out
of scope. The specifications are ECMA-376 Parts 1 to 3 (5th edition), [MS-DOC], [MS-CFB],
[MS-OLEPS], [MS-OSHARED], [MS-ODRAW] and PKWARE's APPNOTE.TXT; `ledger/Ledger/Scope.lean`
names the clauses of each that must have a row.

The ledger is checked by Lean 4 on every push (`make ledger-gate`). Six theorems in
`ledger/Ledger/Gate.lean` establish that every row sits in its own specification's file and
names one of its chapters, that rows are unique, that every required clause has a row speaking
to it, that every implemented row is cited by both implementation code and a test in the source
tree, that every incomplete row is cited by implementation code and explains what is missing,
that every other row explains itself, and that no citation names a clause its specification does
not have. They are decided by Lean's compiled evaluator (`native_decide`), so they trust the Lean
compiler as well as its kernel; the theorems of the reference implementations in
`ledger/Ledger/Reference/`, whose vectors the Rust tests replay, are checked by the kernel alone.
Citation counts below are the number of source comments naming the clause or a sub-clause of it,
in implementation code and in tests.
